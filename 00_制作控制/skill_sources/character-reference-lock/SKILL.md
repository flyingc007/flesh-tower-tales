# Character Reference Lock（通用角色参考锁定协议）

## 原理（为什么参考图会被"魔改"）

文生图模型优先解读文字、倾向于自行美化或补全。只丢参考图而不附加强约束契约文本时，参考图只会被当成"风格参考"，而非"身份锁定卡"——于是容貌、服饰、肤色、道具常被模型脑补改写。

本协议的精髓：**给 AI 划定边界**——一份【默认冻结全集】明确什么不能动，一份【唯一可变域】明确只有用户写出的项目能动，其余全部冻结。不给 AI 自由发挥空间。

## 触发条件

同时满足以下两点即激活本协议：
1. 用户上传了角色参考图（三视图 / turnaround / 角色设定表，含正面、侧面、背面；单张正面图也可触发但锁定力较弱）。
2. 用户意图：复用该角色本体，只做指定局部变更，不允许自由魔改角色本身。

无角色参考图时本协议自动失效，不干预正常生图。

## 核心契约

### 总原则
以用户提供的角色参考图作为**角色基准源**，文字描述只用于控制"可变域"，不得改写"冻结域"。

### 🔒 默认冻结全集（激活即自动生效，无需用户填写）
以下类目全部属于禁止修改范围：
- 容貌类：脸型、五官结构、五官相对位置、面部特征、样貌、原生肤色、面部标记/痣/印记。
- 毛发/体表类：发型、毛发样式与配色、角/耳/鳍/斑纹、鳞片/皮甲/体表纹理、生物特有外形特征。
- 服饰装备类：服装款式、剪裁结构、褶皱样式、服饰配色、材质质感、配饰、护甲。
- 器械道具类：武器、法器、手持物件、底座、容器；道具的结构、造型、配色、数量。
- 形体基础类：角色物种、基础身体比例、肢体结构、标志性身体轮廓。

默认禁止行为清单：换脸、微调五官、增减装饰、修改纹样、变更道具款式、改动角色固有特征、以画风重绘角色本体。

### ✏️ 唯一可变域（仅用户显式授权项）
AI 只能修改用户在提示词里**明确写明、单独列出**的项目。常见合法可变项（仅作识别参考，非默认允许）：
- 角色姿势、肢体动态。
- 镜头角度、构图。
- 环境、背景、场景。
- 光照、打光氛围、色调（不含角色本身固有色）。
- 渲染风格（PBR/卡通/水墨等，前提是不扭曲角色造型容貌）。

> 用户未写明任何可修改项 → 视为【完全锁定，原样复刻参考图】，AI 不得自行改动任何内容。

## 边界判定规则（解决"死板照做 / 乱魔改"两个极端）

1. 用户写了可变项 → 只动这几项；冻结集一丝不动。
2. 用户没有写可变项 → 严格原样复刻，不做任何自主发挥。
3. 文字描述与参考图本体冲突时：**参考图优先级高于文字描述**。文字不能用于改写冻结域。例：参考图为蓝色螺发佛陀，用户文字写"改成黑色头发"→ 属修改冻结域，应拒绝并提示：该特征属于角色锁定项，如需修改角色本体请先解除锁定或追加解锁。
4. 模糊话术拦截：用户写"稍微调整、美化一下、优化细节、变得更好看"等模糊描述 → 不视作合法可变指令，忽略并维持冻结集不变，提示用户明确写出要修改的具体项目。

## 工作流（生图时按此执行）

1. 判定触发条件是否满足；不满足则按正常生图处理。
2. 解析用户是否给出【可变项】与是否出现【模糊话术/冻结域冲突】。
3. 若存在冲突或模糊指令，按"边界判定规则"处理，必要时先用应答话术提示（见 prompt-templates.md）。
4. 按 prompt-templates.md 的模板自动拼接带强约束契约的提示词与负面词，传入文生图/图生图工具。
5. 如生图工具支持参考相似度参数，按 prompt-templates.md 中的参数建议取值。
